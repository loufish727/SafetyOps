# SafetyOps Known Risks

| ID | Severity | Risk and current evidence | Required mitigation / release gate | LFES |
|---|---:|---|---|---|
| SO-R01 | High | The hosted migration ledger is aligned through `012`, and `010`–`012` compiled/applied in the final compatibility sequence. Exact legacy applied-file identity, catalog assertions, and hostile-role behavior have not been proven. | Inspect the hosted catalog, record a reproducible clean replay when Docker is available, and run direct API/RPC tests across disposable companies and roles before real operational use. | LFES-DB-002, LFES-DB-006 |
| SO-R02 | Critical | RLS, database-authoritative role denial, personnel visibility, company isolation, and location isolation have not run against PostgreSQL. Browser helpers are not database proof. | Test every role across at least two companies and assigned/unassigned locations through Data API, RPC, Storage, and UI paths. | LFES-SEC-001, LFES-SEC-002 |
| SO-R03 | High | The last signed public release has CI proof, but that approval applies only to the exact attested build and sanitized release tree. Any file change invalidates that evidence. | Rebuild and create a new local-denylist Ed25519 v2 attestation for every release revision; require strict CI verification before deploy. | LFES-SEC-003, LFES-DEP-005 |
| SO-R04 | High | `sign-form-file` exists as source design, but there is no live upload, quarantine, malware-scan, or commit pipeline. | Deploy and test the narrow download service and a complete prepare/quarantine/scan/commit upload path before enabling private-file controls. | LFES-SEC-002, LFES-OBS-001 |
| SO-R05 | High | The federal eCFR corpus is a dated structural index current through `2026-07-29`; the OR/WA/CA corpus is curated high-use guidance, not a complete state-law corpus. | Add controlled source snapshots and change monitoring, preserve dates/fingerprints, and require qualified applicability review. | LFES-TRACE-001, LFES-OBS-001 |
| SO-R06 | High | Company safety programs, forms, and appendices are not populated by a deployed ingestion path. Public program collections intentionally contain no tenant records. | Import through a tenant-authorized process that preserves original bytes, SHA-256, source lineage, review state, and private Storage identity. | LFES-DB-004, LFES-EVOL-001 |
| SO-R07 | Medium | Browser queries use bounded caps, but large histories can be truncated because user-visible pagination and continuation handling are not implemented. | Add server-side pagination, truncation notices, and load-on-demand detail views before scale testing. | LFES-SCL-001, LFES-SCL-002 |
| SO-R08 | Medium | Program-form save remains a multi-step flow. A mid-flow error can leave a recoverable draft. Migration `010` designs server-derived signatures and final evidence hashes, but real transaction behavior is unproven. | Add idempotent resume/cleanup behavior and transaction-focused database/hosted tests. | LFES-REL-001, LFES-REL-002 |
| SO-R09 | Medium | The application is online-first. Offline queues, conflicts, reconnect retries, and weak-network behavior are unproven. | Define mutation idempotency and conflict policy; test loss/retry behavior for every critical workflow. | LFES-MOB-002, LFES-REL-004 |
| SO-R10 | Medium | `app.js` concentrates auth, data access, mapping, rendering, events, and mutations. | Refactor through scoped plans, dependency maps, targeted tests, checkpoints, and rollback. | LFES-MNT-001, LFES-EVOL-002 |
| SO-R11 | High | No database backup, restore, rollback, or forward-correction exercise is recorded. | Establish backups and rehearse data-preserving recovery before storing real tenant data. | LFES-DEP-004, LFES-EVOL-001 |
| SO-R12 | Medium | The 67-pass desktop/mobile browser suite is current, but real-device, accessibility, and weak-network sessions remain unproven. | Complete keyboard/accessibility review and real-device auth/workflow/weak-network smoke tests. | LFES-MOB-001, LFES-MOB-003 |
| SO-R13 | Critical | The working source repository has private tenant material in prior Git history. Deleting current files does not remove that history. | Never publish the working repository history; publish only the scanned, sanitized, clean-history release tree. | LFES-SEC-003, LFES-DEP-003 |
| SO-R14 | Medium | Release authority depends on custody, backup, rotation, and recovery of the Ed25519 private key and ignored local tenant denylist. | Document owners and recovery/rotation procedures; keep both inputs outside Git and require them for release approval. | LFES-SEC-003, LFES-DEP-005 |
| SO-R15 | Medium | The Supabase browser client is locally vendored and digest-pinned, but dependency upgrades still require deliberate provenance and compatibility review. | Record the approved source/digest and repeat boundary, CSP, and browser tests for every vendor update. | LFES-SEC-003, LFES-EVOL-002 |
| SO-R16 | Medium | Development IndexedDB staging was previously enabled; old form blobs can remain on a device even though production staging is disabled. | Provide and verify a visible local-staging cleanup path before handling real forms. | LFES-REL-005, LFES-MOB-002 |
| SO-R17 | High | Persistent Supabase auth is disabled on the shared `github.io` origin because that origin is not a safe long-term tenant session boundary. | Use a controlled custom domain and complete session, recovery, sign-out, origin, and cache testing before enabling persistence. | LFES-SEC-001, LFES-DEP-005 |
| SO-R18 | High | The hosted release is connected and its initial tenant bootstrap is verified, but authenticated workflows, Edge Function, file services, and role isolation remain unproven. | Do not label the connected shell production-ready; complete the authenticated role matrix, hosted workflows, recovery, and compliance gates first. | LFES-VER-001, LFES-DEP-001 |
| SO-R19 | High | Production SMTP is not configured or proven. Supabase's default Auth sender refuses non-team addresses and is best-effort, so external invitation and recovery delivery cannot be relied on. | Configure a controlled SMTP provider with SPF/DKIM/DMARC and link tracking disabled; verify invitation, expiry, replay denial, recovery, and non-enumerating errors before production use. | LFES-SEC-005, LFES-REL-005 |
| SO-R20 | High | The product does not yet expose a reviewed Auth invitation and membership-grant service for additional administrators or safety managers. A human-prepared regulatory profile requires a different authorized reviewer. | Implement an administrator-only invitation/membership workflow with database-derived inviter/audit evidence and prove last-admin, role, location, expired-invite, and cross-tenant denials before approving regulatory profiles. | LFES-SEC-001, LFES-OBS-001 |

Risk acceptance must name an owner, scope, expiry/review date, and
compensating control. Critical tenant-isolation and private-file risks cannot
be accepted for production through UI-only mitigation.
